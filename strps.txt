================================================================

  2. Node.js 18+           https://nodejs.org  (LTS version)
  3. Git                   https://git-scm.com
  4. MongoDB Community     https://mongodb.com/try/download/community
                           (choose "Install as service" — runs on boot)
  5. Tesseract OCR         https://github.com/UB-Mannheim/tesseract/wiki
                           (Windows installer; default path is fine.
                            Needed ONLY for photo/JPG reading.)

[WEB] Create these free accounts once:
  a. Telegram account (you have it)
  b. my.telegram.org     → API development tools → note
        API_ID  and  API_HASH
  c. Telegram: chat with @BotFather → /newbot → copy the
        BOT TOKEN ; then chat with @userinfobot → copy your
        numeric user id (= CHAT_ID)
  d. (Optional, later) GitHub / Render / Vercel / MongoDB Atlas
        accounts for the hosting part.

PART 1 — INSTALL ON PC (LOCAL RUN)
================================================================

STEP 1 — Get the code
  [PC]  git clone <your-repo-url> "placement tracker"
        cd "placement tracker"

STEP 2 — Backend dependencies
  [PC]  cd backend
        python -m venv venv
        venv\Scripts\activate            (PowerShell: .\venv\Scripts\Activate.ps1)
        pip install -r requirements.txt
        python -m spacy download en_core_web_sm
        python -m spacy validate         (should say the model is OK)

STEP 3 — Environment file
  [PC]  copy .env.example .env
        Open .env in any editor and fill in:
          ADMIN_USERNAME / ADMIN_PASSWORD / ADMIN_SECURITY_CODE
              -> your dashboard login (pick STRONG values)
          JWT_SECRET       -> run in terminal:  openssl rand -hex 32
                              and paste the output
          MONGODB_URI      -> mongodb://localhost:27017
          TELEGRAM_API_ID / TELEGRAM_API_HASH   (from Part 0-b)
          TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID (from Part 0-c)
          PLACEMENT_GROUP_ID -> open your placement group in
              Telegram Web, the URL ends like #-1234567890;
              that number (with minus) is the group id
          STUDENT_NAME=Sunil T , STUDENT_USN=1DS24CS421
          GEMINI_API_KEY=   (OPTIONAL - system runs fully offline
              without it; with a key, extraction gets smarter and the
              Gemini chat page unlocks after its own Enable press)

STEP 4 — One-time Telegram session
  [PC]  python setup_session.py
        -> enter phone number, login code, (2FA password if set)
        -> it prints/stores TELEGRAM_SESSION_STRING
        -> paste that string into .env

STEP 4b — ACTIVATE THE BOT (do not skip!)
  [PH]  Open Telegram -> search your bot's username -> press START
        -> send any message once.
        Telegram FORBIDS bots from messaging users who never started
        them. Skipping this = every alert fails with "chat not found".
        The backend now self-tests this on every boot: if you see
        "STARTUP PING FAILED" in the console, this step was missed.

STEP 5 — Run everything
  Terminal A:                          Terminal B:
    cd backend                          cd frontend
    venv activated                      npm install
    uvicorn main:app --reload           npm run dev
    (use --reload ONLY for development. If you ever see
     "Conflict: terminated by other getUpdates request",
     an old worker survived Ctrl+C — kill stray python
     processes and start clean.)
  Backend API docs: http://localhost:8000/docs
  Dashboard:        http://localhost:5173

STEP 6 — Verify it's alive
  [PC] http://localhost:5173 → login with ADMIN creds
       Dashboard should show stats; bot should greet on /start
       Forward any message from the placement group to your bot —
       within seconds it should appear under Messages page.


================================================================
PART 2 — USE ON MOBILE (WHILE HOSTED ON YOUR PC)
================================================================

Your backend is on the PC; the phone just opens the dashboard.

STEP 1 — Find your PC's IP
  [PC]  ipconfig    → look for "IPv4 Address", e.g. 192.168.1.7

STEP 2 — Expose dev servers to LAN
  [PC]  Frontend:  npm run dev -- --host
        Backend:   uvicorn main:app --host 0.0.0.0 --port 8000

STEP 3 — Point frontend at the PC
  [PC]  In frontend create/edit .env :
          VITE_API_URL=http://192.168.1.7:8000
        Restart  npm run dev -- --host

STEP 4 — Allow CORS for the phone origin
  [PC]  In backend .env add your origins (comma separated):
          CORS_ORIGINS=["http://localhost:5173","http://192.168.1.7:5173"]

STEP 5 — Open on phone
  [PH]  Same Wi-Fi as PC → Chrome → http://192.168.1.7:5173
        Login once; token stays until you log out.
  Tip: Chrome menu ⋮ → "Add to Home screen" gives you an
  app-like icon (real PWA comes later).

NOTES
  • Phone access only works while the PC is ON and both are on
    the same network. For anywhere-access use Part 4 hosting.
  • Telegram alerts reach your phone 24/7 regardless of the
    dashboard, because alerts come from the bot, not the site.

================================================================

      -> no real values committed anywhere (docs included).
         Old README had REAL credentials — verify they're gone
         from git history or treat them as burned/rotated.
  [ ] .env is NOT tracked:  git status must not list it
  [ ] Strong JWT_SECRET + ADMIN_PASSWORD generated fresh
  [ ] Tests green:      cd backend && python -m pytest tests/ -q
  [ ] Frontend builds:  cd frontend && npm run build
  [ ] requirements.txt current (PyJWT, openpyxl, pytesseract, Pillow…)
  [ ] Decide MongoDB: local (dies with PC) vs Atlas (always-on)
  [ ] Know the limitation: Telethon userbot needs a ALWAYS-ON
      process. Free tiers that sleep (Render free) will pause
      live listening while asleep — alerts resume on wake.


================================================================
PART 4 — FREE-TIER DEPLOYMENT (STEP BY STEP)
================================================================

Recommended free stack (total cost: ₹0):

  Database : MongoDB Atlas M0 (512 MB, forever-free)
  Backend  : Render.com free Web Service (750 h/mo, sleeps idle)
             — alternative: Koyeb free instance
  Frontend : Vercel Hobby (or Netlify free)
  Telegram : unchanged — bots/userbot run inside your backend

------------------------------------------------------------
4A. MongoDB Atlas (database)
------------------------------------------------------------
 1.[WEB] mongodb.com/atlas → sign up → Build FREE cluster (M0)
 2. Region: pick one close to where you'll host the backend
    (e.g. Singapore/Mumbai for India).
 3. Database Access → Add user → username+password (SAVE IT)
 4. Network Access → Add IP → 0.0.0.0/0 (allow all; needed
    because free PaaS egress IPs change)
 5. Clusters → Connect → Drivers → copy URI, looks like:
      mongodb+srv://USER:PASS@cluster0.xxxxx.mongodb.net/
    Append db name:  ...mongodb.net/placement_monitor
    This = your new MONGODB_URI

------------------------------------------------------------
4B. Push code to GitHub
------------------------------------------------------------
 1.[PC]  git add . && git commit -m "prepare deploy"
 2. Create empty repo on github.com, then:
        git remote add origin https://github.com/YOU/placementos.git
        git push -u origin main
 (repo must contain NO .env, NO *.session)

------------------------------------------------------------
4C. Backend on Render.com
------------------------------------------------------------
 1.[WEB] render.com → sign in with GitHub → New + → Web Service
 2. Pick the repo. Settings:
      Root Directory:      backend
      Runtime:             Python 3
      Build Command:       pip install -r requirements.txt &&
                           python -m spacy download en_core_web_sm
      Start Command:       uvicorn main:app --host 0.0.0.0 --port $PORT
      Instance Type:       Free
 3. Environment → add EVERY variable from your local .env,
    but now:
      MONGODB_URI        = the Atlas URI from 4A
      JWT_SECRET         = NEW strong value (not the dev one)
      ADMIN_PASSWORD     = NEW strong value
      CORS_ORIGINS       = ["https://YOUR-APP.vercel.app"]
                           (fill after 4D; edit again then)
      TELEGRAM_SESSION_STRING = paste from Part 1 Step 4
 4. Deploy → wait for build (~5 min first time) → you get
      https://placementos-api.onrender.com
 5. Test:  open  /api/health  in browser → {"status":"ok"}

 RENDER FREE CAVEATS
  • Sleeps after ~15 min idle → cold start ~50 s on next hit.
  • While asleep the userbot is OFF (no live listening).
    Workaround: a free uptime pinger (cron-job.org hitting
    /api/health every 10 min) keeps it awake most of the day.
  • Free disk resets on redeploy → downloaded PDFs vanish;
    DB records remain (links still work).

------------------------------------------------------------
4D. Frontend on Vercel
------------------------------------------------------------
 1.[WEB] vercel.com → sign in with GitHub → Add New → Project
 2. Import the repo. Settings:
      Root Directory:      frontend
      Framework Preset:    Vite   (auto-detected)
      Build Command:       npm run build
      Output Directory:    dist
      Environment var:     VITE_API_URL =
                           https://placementos-api.onrender.com
 3. Deploy → you get  https://YOUR-APP.vercel.app
 4.[WEB] Go BACK to Render → Environment → make sure
      CORS_ORIGINS includes this exact Vercel URL, e.g.
      ["https://YOUR-APP.vercel.app"]
      → Save (service redeploys automatically).

------------------------------------------------------------
4E. First cloud login
------------------------------------------------------------
 1.[PH/PC] Open the Vercel URL → login with the CLOUD admin
    credentials you set in 4C (they differ from local!).
 2. Dashboard loads from Atlas data → done.


================================================================
PART 5 — AFTER DEPLOYMENT VERIFICATION
================================================================

  1. Health:      https://...onrender.com/api/health → ok
  2. Docs:        /docs returns 404 BY DEFAULT (security). To view
                  Swagger on the cloud, set DOCS_ENABLED=true in
                  Render env vars (turn it back off afterwards).
  3. Startup ping: backend log shows "Startup ping delivered" AND
                  your Telegram gets "PlacementOS is online".
                  If not → press START on the bot, check chat id.
 3. Login:       Vercel app → wrong password REJECTED, right one logs in
 4. Bot:         Telegram → /start on your bot → replies
 5. Live loop:   post a test message in the placement group
                 (or forward one to the bot) → appears in Messages
                 within seconds; if it contains a deadline →
                 reminder created; if Excel sheet w/ your USN → 🎉
 6. Filters:     Opportunities page → role filter "Any Role Match"
                 and "📝 Form Drives" toggle work
 7. Logs:        Render dashboard → Logs tab → check userbot
                 connected, scheduler jobs firing hourly
 8. Uptime:      set cron-job.org → GET /api/health every 10 min
                 (keeps Render awake + monitors downtime)
 9. Backups:     Atlas free tier has no auto-backup — monthly,
                 export manually (Compass or mongodump).

ROLLBACK / FIX LOOP
  Every  git push  to main auto-redeploys Render + Vercel.
  Broke something? Revert commit and push again.
