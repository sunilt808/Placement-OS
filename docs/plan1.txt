AI PLACEMENT MONITOR — FINAL PLAN

1. OBJECTIVE

Build a personal AI-powered placement monitoring system that prevents missed college placement opportunities.

Problem:
The college placement department sends 100+ Telegram messages per day. Important company announcements, deadlines, eligibility and registration links get buried.

Primary goal:
NEVER MISS A PLACEMENT OPPORTUNITY BECAUSE THE MESSAGE WAS OVERLOOKED.

The system should prioritize recall over precision. A false alert is acceptable; a missed genuine opportunity is not.

--------------------------------------------------
2. IMPORTANT TELEGRAM CONSTRAINT
--------------------------------------------------

The college group may not allow our bot to be added.

Therefore DO NOT depend on direct bot access to the college group.

Use two ingestion methods:

A. HISTORICAL DATA
Export approximately the previous one month of Telegram chat history.

Prefer Telegram JSON export because it is structured and easier to parse.

Import:
- JSON
- CSV if available
- TXT
- HTML as fallback

B. NEW MESSAGES
Initially, the student manually forwards new/relevant messages from the college group to the student's personal Telegram bot.

The architecture must be modular so a Telegram user-account/client ingestion layer can optionally be added later if legally/technically appropriate and permitted.

Do not attempt to bypass Telegram restrictions, protected content, group permissions, or college policies.

--------------------------------------------------
5. CORE PRINCIPLE: AI VS BACKEND
--------------------------------------------------

Gemini should understand messages.

Python/backend should control application state.

Gemini:
"What does this message mean?"

Backend:
"What is the current state of this opportunity?"

Do NOT ask the AI to calculate reminders or maintain application state.

Example:

Gemini extracts:
deadline = 2026-08-25 17:00

Python:
- stores timezone-aware datetime
- calculates remaining time
- schedules reminder
- determines expired/today/tomorrow

This makes the system deterministic and reliable.

29. PRIVACY
--------------------------------------------------

Placement messages may contain private college information.

Therefore:

- Keep the database private.
- Do not publicly expose imported messages.
- Do not send data to unrelated third parties.
- Store only required information.
- Secure the Telegram bot.
- Protect any Telegram session credentials if a future user-account client is added.

Do not bypass protected Telegram content or access controls.

--------------------------------------------------
30. FAILURE HANDLING
--------------------------------------------------

Handle:

- empty messages
- malformed Telegram exports
- unsupported files
- missing dates
- ambiguous dates
- Gemini API failures
- Gemini rate limits
- MongoDB failures
- duplicate messages
- invalid links
- AI extraction errors

If AI fails:

1. Preserve original message.
2. Mark as pending retry.
3. Retry later.
4. Never lose the message.

--------------------------------------------------
32. AI MODEL STRATEGY
--------------------------------------------------

Preferred runtime:

Gemini because this is primarily:
- classification
- structured extraction
- information normalization

Use a fast/cheap Gemini model for normal messages.

Use a stronger model only for:
- ambiguous messages
- complicated multi-message updates
- difficult eligibility interpretation
- complex document extraction

Claude/GPT can be used as development/review assistants, but the production AI should be selected based on actual test accuracy and cost on the student's real placement messages.

Do not choose a model only because it is generally considered "smarter."

Create a test dataset from real historical placement messages and compare models on:

- classification accuracy
- company extraction
- CTC extraction
- deadline extraction
- eligibility extraction
- duplicate/update detection
- JSON validity
- cost
- latency

39. SUCCESS CRITERIA
--------------------------------------------------

The system is successful when:

1. A forwarded message is recognized.
2. Company/CTC/deadline/eligibility are extracted when present.
3. Original message is preserved.
4. Opportunity is stored.
5. User receives an alert.
6. Duplicate announcements do not create duplicate jobs.
7. Deadline extensions update the existing job.
8. Reminders work.
9. Applied status stops unnecessary reminders.
10. Historical Telegram JSON can be imported.
11. Old opportunities can be recovered.
12. Dashboard shows what needs attention now.
13. System works without adding a bot to the college group.
14. AI failures do not cause message loss.
